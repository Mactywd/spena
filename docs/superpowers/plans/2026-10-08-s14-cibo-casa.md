# S14 — «Tutto / Cibo / Casa» in dispensa: piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** nella Dispensa, quando ci sono sia cibo sia cose di casa, tre pulsanti «Tutto / Cibo / Casa» sotto la barra fanno vedere un mondo alla volta; la scelta si ricorda per la sessione, il riepilogo delle scadenze conta il mondo scelto, e nessun filtro lascia un vicolo cieco.

**Architecture:** il server dice di che mondo è ogni voce (`PantryItemOut.ingredient_kind`, letto da `ingredients.kind`, come fa già `ShoppingItemOut`); il client confronta quel verdetto, non lo ricava dal reparto. In `pantryView.ts` nascono le funzioni pure del mondo (`inWorld`, `hasBothWorlds`, `visibleItems` che compone mondo → ricerca → scadenze, `settleWorld` che decide quando tornare a «Tutto»); `pantryWorld.ts` ricorda la scelta in `sessionStorage` senza mai lanciare; `WorldSelector.tsx` disegna i tre pulsanti con `Button` e `aria-pressed`; `PantryScreen.tsx` li collega. Nessuna rotta nuova, nessuna migrazione, nessun token di colore nuovo.

**Tech Stack:** FastAPI + Pydantic, pytest su Postgres vero; React 19, TypeScript, Tailwind 4 (token in `@theme`), TanStack Query 5, Vitest + Testing Library (jsdom), Playwright.

**Spec:** `docs/superpowers/specs/2026-10-06-cibo-casa-bozza.md` (tutta; le decisioni del §6 sono di Mattia, 2026-10-07) e la voce **S14** di `docs/prossimi-passi.md`. Si legge insieme a `docs/superpowers/specs/2026-10-06-reparti-collassabili-bozza.md` (S15, il piano che viene dopo questo sullo stesso schermo).

## Obiettivo e contesto

Dal 2026-09-17 (D4) cibo e non alimentari stanno nella stessa dispensa, con gli stessi tre stati: il detersivo accanto allo yogurt. Chi guarda cosa può cucinare non vuole scorrere le cose di casa, chi controlla le cose di casa non vuole trenta righe di cibo. Il modello ha già la distinzione (`ingredients.kind`, derivato dal reparto), ma `PantryItemOut` non la porta, e il client non deve ricavarla dal reparto: sarebbe una seconda copia di `kind_for_category`, la prima lezione di `CLAUDE.md`. Questo piano espone il verdetto, aggiunge il selettore, e lo incastra con la ricerca (S11), il riepilogo delle scadenze e l'aggiunta senza lasciare vicoli ciechi.

## Decisioni prese

Da Mattia, il 2026-10-07 (§6 della bozza), non si rimettono in discussione:

1. **Il server espone `ingredient_kind`** (strada A): `PantryItemOut.ingredient_kind`, letto da `item.ingredient.kind` in `_to_out`. Il client riceve tutta la dispensa come oggi, una chiave di cache sola (`["pantry"]`), e filtra con un confronto di uguaglianza. Niente `?kind=` nella rotta.
2. **`sessionStorage` e non `localStorage`**, chiave `spena.dispensa.mondo`, con un involucro che non lancia se lo spazio del sito è bloccato, come `recipeFilters.ts`: chiusa l'app, la dispensa riparte intera.
3. **Il selettore è nascosto quando la dispensa ha un mondo solo**, e vale «Tutto». Se sparisce mentre era su un mondo, torna a «Tutto» nello stesso disegno.
4. **Il nome è «Casa»** per `non_food` (i reparti `casa` e `igiene`). I tre pulsanti: «Tutto», «Cibo», «Casa».
5. **Il riepilogo delle scadenze conta il mondo scelto.**

Dalla bozza (§3–§5), già decise e qui solo messe in codice:

6. **L'ordine dei filtri è uno**, in una funzione pura di `pantryView.ts`: mondo → ricerca (`matchesQuery`) → in scadenza (`hasExpiry`, col riepilogo premuto) → raggruppamento per reparto (`groupForDisplay`). Un reparto senza voci del mondo scelto sparisce intero, perché `groupForDisplay` riceve solo le voci a video.
7. **Ricerca vuota nel mondo scelto**: «Niente in Casa per «…»» con «Cerca in tutto» (passa a «Tutto» e tiene il testo), **al posto** dell'offerta di aggiungere, che torna solo su «Tutto». Col riepilogo premuto resta per primo il vuoto di oggi («Niente in scadenza per «…»» con «Mostra tutto», che spegne solo il riepilogo): si toglie un filtro alla volta, dal più stretto.
8. **«Dispensa vuota»** resta il messaggio della dispensa davvero vuota.
9. **Nessun colore nuovo**: il pulsante premuto usa token che l'app ha già.

Scelte di questo piano, dove la bozza non arrivava (**decise da Claude su delega di Mattia**: estetiche o tecniche interne, reversibili):

10. **Il selettore sta in `features/pantry/WorldSelector.tsx`**, non in `components/ui/`: la bozza voleva un `SegmentedControl` comune solo se ci fosse un secondo uso, e non c'è (Lista e Sistema la spesa sono fuori scope, §7).
11. **I tre pulsanti sono `Button` a pastiglia, a larghezza uguale (`flex-1`), `primary` il premuto e `secondary` gli altri**, dentro un `role="group"` col nome «Cosa mostrare». È la forma del gradino scelto di «Cosa posso cucinare» (`MissingBudgetFilter.tsx`, `buttonClasses(checked ? "primary" : "secondary", "pill")`), cioè l'unico altro posto dell'app dove si sceglie uno fra pochi: l'ambra di `aria-pressed` del riepilogo è il colore delle scadenze, e su un selettore di mondi direbbe una cosa che non c'entra. Pulsanti e non radio, come chiede la bozza (`aria-pressed`, uno solo premuto); ritoccare quello premuto non fa niente.
12. **Il selettore sta subito sopra il riepilogo delle scadenze**, cioè sotto la barra e sotto il pannello dell'aggiunta quando è aperto: S3 apre il suo pannello «sotto la barra», e il pannello di un gesto in corso resta attaccato al campo da cui parte.
13. **Il vuoto del mondo dice il nome del pulsante**: «Niente in Casa per «sale»», «Niente in Cibo per «sale»» — la parola che chi guarda ha appena toccato.
14. **Quando tornare a «Tutto» è una funzione pura sola**, `settleWorld(world, items, revealId)`, chiamata nel disegno (come il riepilogo che sparisce, e per la stessa ragione: nessun giro con un filtro fantasma). Copre le due uscite — il selettore che sparisce, e la voce appena aggiunta (`revealId`) dell'altro mondo — senza toccare i gestori dell'aggiunta: così vale per ogni strada con cui S3 aggiunge (il +, la scansione, la serie) senza conoscerle.
15. **«Voci attive» (bozza §3) sono le voci che `GET /pantry` restituisce**, cioè le non archiviate, finite comprese: una cosa di casa finita è a video, col suo «In lista», e il selettore deve poterla mostrare da sola.
16. **Il mondo si ricorda solo dopo il primo caricamento riuscito**: prima, la dispensa vuota del caricamento non deve riportare a «Tutto» una scelta valida.

**Deciso da Mattia il 2026-10-09:** la bozza (§4) dice che aggiungendo **una voce dell'altro mondo** il selettore passa a «Tutto». Non dice cosa succede aggiungendo **una voce dello stesso mondo** (sono su «Casa» e aggiungo l'ammorbidente). Il piano **lascia il mondo com'è** in quel caso: la riga nuova si vede già, e cambiare il filtro senza bisogno sarebbe un cambiamento non chiesto. Lo fissa un test (Task 5, «una voce aggiunta dello stesso mondo lascia il mondo com'è»). L'alternativa — passare sempre a «Tutto», come oggi la barra si svuota sempre — è una riga in `settleWorld` e la migrazione di quel test.

```ts
/** Il mondo che la Dispensa mostra (S14): tutto, solo il cibo, solo le cose di casa.
 * «Casa» è `non_food`, cioè i reparti `casa` e `igiene`; quale voce stia dove lo dice il
 * server (`ingredient_kind`), non questo file. */
export type PantryWorld = "all" | "food" | "non_food";

/** L'ordine dei pulsanti del selettore. */
export const WORLDS: readonly PantryWorld[] = ["all", "food", "non_food"];

/** I nomi a video, decisi da Mattia il 2026-10-07: «Casa» e non «Non alimentari», che a
 * 375 px non ci sta. Servono anche al vuoto del mondo («Niente in Casa per «…»»). */
export const WORLD_LABELS: Record<PantryWorld, string> = {
  all: "Tutto",
  food: "Cibo",
  non_food: "Casa",
};

/** Se la voce sta nel mondo scelto. Un confronto su un verdetto del server e non un
 * calcolo: il mondo discende dal reparto in `kind_for_category`, nel backend, e una
 * seconda copia qui resterebbe indietro il giorno in cui un reparto cambia mondo. */
export function inWorld(item: PantryItem, world: PantryWorld): boolean {
  return world === "all" || item.ingredient_kind === world;
}

/** Se in dispensa ci sono voci dei due mondi: solo allora il selettore serve (bozza S14
 * §3). Con un mondo solo, ogni scelta diversa da «Tutto» potrebbe solo svuotare la
 * pagina. Contano tutte le voci che arrivano, finite comprese: sono a video. */
export function hasBothWorlds(items: PantryItem[]): boolean {
  return (
    items.some((item) => item.ingredient_kind === "food") &&
    items.some((item) => item.ingredient_kind === "non_food")
  );
}

/** Quel che chi guarda ha chiesto alla Dispensa: il mondo, il testo della barra, il
 * riepilogo delle scadenze premuto. */
export interface PantryView {
  world: PantryWorld;
  query: string;
  expiringOnly: boolean;
}

/** Le voci a video, coi filtri in un ordine solo (bozza S14 §4): mondo, ricerca (S11),
 * in scadenza. Il raggruppamento per reparto viene dopo (`groupForDisplay`), e un reparto
 * senza voci del mondo scelto sparisce intero: non è chiuso, non c'è. */
export function visibleItems(items: PantryItem[], view: PantryView): PantryItem[] {
  return items
    .filter((item) => inWorld(item, view.world))
    .filter((item) => matchesQuery(item, view.query))
    .filter((item) => !view.expiringOnly || hasExpiry(item));
}

/** Il mondo da applicare davvero, dato quello scelto. Torna «Tutto» in due casi:
 * - il selettore non c'è più (un mondo solo): una dispensa vuota per un filtro che non si
 *   vede sarebbe una bugia, come per il riepilogo delle scadenze che sparisce;
 * - la voce appena aggiunta (`revealId`) è dell'altro mondo: deve potersi vedere, come
 *   dopo un'aggiunta la barra si svuota e il riepilogo si spegne.
 * Una voce appena aggiunta dello stesso mondo si vede già, e il mondo resta. Una che non
 * è ancora arrivata nell'elenco non cambia niente: se ne riparla quando arriva. */
export function settleWorld(
  world: PantryWorld,
  items: PantryItem[],
  revealId: string | null
): PantryWorld {
  if (world === "all") return world;
  if (!hasBothWorlds(items)) return "all";
  const revealed = revealId === null ? undefined : items.find((item) => item.id === revealId);
  if (revealed !== undefined && !inWorld(revealed, world)) return "all";
  return world;
}
```

/** Dove il mondo scelto in Dispensa si ricorda finché l'app è aperta (S14, Mattia
 * 2026-10-07). `sessionStorage` e non `localStorage`, come i filtri del ricettario
 * (`recipeFilters.ts`): chiusa l'app, la dispensa riparte intera, invece di aprirsi su

export const WORLD_KEY = "spena.dispensa.mondo";

/** La `sessionStorage`, se si riesce ad aprirla: già leggerla può lanciare (dati del sito
 * bloccati), quindi anche l'accesso sta nel try. */
function sessionStore(): Storage | null {
  try {
    return globalThis.sessionStorage ?? null;
  } catch {
    return null;
  }
}

/** Il mondo ricordato, o «Tutto». Un valore che non si riconosce vale «Tutto»: il ricordo
 * è una comodità, e una scelta illeggibile non deve nascondere niente. */
export function loadWorld(store: Storage | null = sessionStore()): PantryWorld {
  if (store === null) return "all";
  try {
    const saved = store.getItem(WORLD_KEY);
    return WORLDS.find((world) => world === saved) ?? "all";
  } catch {
    return "all";
  }
}

 * schermo è aperto. */

  if (store === null) return;
  try {
    store.setItem(WORLD_KEY, world);
  } catch {
    // vedi sopra: niente da fare, e niente da dire
  }
}
