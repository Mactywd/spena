# H1, le spese dell'AI: piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** dal ☰ si apre «Spese dell'AI»: quanto è costata l'AI nel periodo scelto («Questo mese» di partenza, «Ultimi 30 giorni», «Da sempre»), come si divide per sezione e giorno per giorno, coi giorni contati a Roma, letto da `llm_calls`.

Nessuna migrazione: l'indice `ix_llm_calls_created_at_call_site` c'è già. Nel frontend una cartella nuova, `frontend/src/features/spending/`: i tipi, la chiamata, le parole (`format.ts`), due grafici in SVG scritto a mano (`SectionBars`, `DailyColumns`) e la schermata `SpendingScreen` su `/spese-ai`, ultima voce del ☰. Nel browser vero le spese si seminano con un aiutante nel container (`backend/tests/e2e_spese.py`), senza rete.

## Obiettivo e contesto

Da T2 (2026-09-17) ogni chiamata all'LLM scrive una riga in `llm_calls` con la sezione che l'ha fatta e il costo che OpenRouter dichiara nella risposta. È stata costruita proprio per questa voce — «la divisione per sezione la teniamo noi» — ma nessuno la legge: la spesa si vede solo sul sito di OpenRouter, tutta insieme. Mattia ha deciso il 2026-10-09 cosa mostrare: il totale del periodo, come si divide per sezione, e l'andamento giorno per giorno; niente elenco delle chiamate né una vista delle fallite; tre periodi, coi giorni di Roma.

## Decisioni prese

Di Mattia, il 2026-10-09:

1. **La schermata mostra sempre il totale del periodo, più la divisione per sezione e l'andamento per giorno.** Niente elenco delle chiamate, niente sezione dedicata alle fallite. Il costo delle fallite entra nei totali se è costo reale.
2. **Periodi:** «Questo mese» di partenza, «Ultimi 30 giorni», «Da sempre» (lo storico parte dal 2026-09-17). **I giorni si contano in Europe/Rome** come la scadenza (`PANTRY_TZ`), non in UTC.

Di Claude, su delega di Mattia (il perché è nella spec, §3):

3. **Le fallite entrano nei totali per quanto costano, cioè niente**: ogni punto di chiamata registra una fallita con `LlmUsage()` vuota, quindi `cost_usd` NULL; sommarla come zero direbbe «gratis». Il totale è la somma dei costi dichiarati e non guarda `ok`; le chiamate senza costo si contano (`unpriced_calls`) e lo dice una riga sotto il totale (decisa da Mattia il 2026-10-13, sotto).
4. **La rotta:** `GET /api/v1/llm-spending?period=month|30d|all`, default `month`, 422 per un altro valore, dietro la sessione. Risponde `period`, `first_day`, `last_day`, `total_usd`, `calls`, `unpriced_calls`, `sections` (`call_site`, `label`, `cost_usd`, `share`, `calls`; dalla più cara, a parità più chiamate, poi il nome) e `days` (`day`, `cost_usd`; ogni giorno del periodo, quelli senza spesa a 0). Costi a 8 decimali, quote a 4, in dollari.
5. **I periodi in giorni di Roma**, «oggi» da `today_in_pantry()`: `month` dal primo del mese a oggi; `30d` i 30 giorni che finiscono oggi; `all` dal giorno della prima chiamata registrata a oggi (senza chiamate, oggi). Un giorno va da mezzanotte a mezzanotte a Roma; nella query diventa un intervallo di istanti `[inizio, inizio del giorno dopo)`.
6. **I nomi delle sezioni** stanno nel backend (`CALL_SITE_LABELS`), per tutte e sei le sezioni compresa quella di S12 (`ingredient_emoji`) e quella di R8 (`recipe_variant`); una sezione sconosciuta torna col suo `call_site` come `label`. Un test fallisce se un valore di `LlmCallSite` non ha il nome.
7. **Dove:** l'ultima voce del ☰, dopo «Anagrafica», percorso `/spese-ai`. **Nome:** «Spese dell'AI» (nel ☰ e come titolo), non «Spese»: sotto «Sistema la spesa» si leggerebbe come lo scontrino.
8. **Il costo all'italiana, in dollari**: «0,025 $»; due decimali da 1 $ in su, fino a quattro (almeno due) sotto; «< 0,0001 $» sotto il decimillesimo; «0,00 $» a zero. Le quote intere, «< 1%» sotto l'uno.
9. **La forma:** il totale in `text-4xl` sotto «Totale, {intervallo}» e sopra il numero delle chiamate; «Per sezione» con una riga e una barra orizzontale (`brand` su `brand-tint`) per sezione; «Per giorno» con colonne SVG `brand` sopra una linea `line`, alte in proporzione al giorno più caro, minimo 2% per un giorno con una spesa, spazio fra le colonne fino a 62 giorni, colonna non più larga di quella con 14 giorni; sopra «Il giorno più caro: …», sotto le date ai due capi. Un colore solo: le sezioni si riconoscono dal nome.
10. **Niente tocco sulle colonne** (sarebbero bersagli da 10 px): il grafico è un'immagine col riassunto nel nome, e una tabella `sr-only` dà i giorni con una spesa.
11. **Il periodo** con tre pulsanti a larghezza uguale in un gruppo «Periodo», quello scelto `primary` con `aria-pressed`, gli altri `secondary` (la forma di S14). Non si ricorda.
12. **Vuoti:** senza chiamate una frase in una scheda, e i pulsanti restano; con chiamate tutte senza costo il totale «0,00 $», il conto e la riga delle senza costo, nessun grafico; guasto → `ErrorState`.

Scelte interne di questo piano (Claude, su delega; reversibili):

13. **I tipi stanno in `frontend/src/features/spending/types.ts`**, non in `domain/types.ts`: li usa solo questa cartella, e `domain/types.ts` lo cambiano S12, S14, S15 e R2 stanotte.
14. **Il fuso nella query è una costante SQL** (`literal_column("'Europe/Rome'")`), non un parametro: la stessa espressione sta nel `SELECT` e nel `GROUP BY`, e con due parametri (`$1`, `$2`) Postgres le considera due espressioni diverse.
15. **Le colonne in un `viewBox` di `n × 102` con `preserveAspectRatio="none"`**: una unità per giorno in larghezza, cento in altezza; la linea di base con `vector-effect="non-scaling-stroke"`, così resta di un pixel. Niente angoli arrotondati: con `none` si deformerebbero.
16. **Nessuna regola di contrasto nuova in `theme.test.ts`**: `brand` su `card` e su `brand-tint` stanno già fra le coppie da 4,5:1, sopra il 3:1 di un segno. Lo misura a video la prova nuova di `style.spec.ts`, con un aiutante che legge il `fill` (`contrastoSegno` legge il `backgroundColor`, che un `<rect>` non ha).

**Deciso da Mattia il 2026-10-13:** la riga sotto il totale che conta le chiamate senza costo dichiarato («3 senza un costo dichiarato da OpenRouter (di solito, chiamate fallite): non sono nel totale.»). Mattia ha escluso una *sezione* delle fallite; questa è una riga sola, che c'è solo quando ce n'è almeno una, e senza di lei il totale sottostimerebbe in silenzio. Si tiene.

```python
"""Le spese dell'AI (H1): i periodi, i giorni, la quota, i nomi delle sezioni.

Puro come `rules.py`: niente database e niente orologio. «Oggi» entra come argomento, ed è
`today_in_pantry()` di chi chiama: un giorno qui è un giorno di calendario a Roma, come la
scadenza, e non un giorno UTC — chi apre l'app a mezzanotte e mezza ha speso oggi.

Le cifre sono quelle che OpenRouter dichiara, in dollari (`llm_calls.cost_usd`). Una
chiamata senza costo dichiarato — tutte le fallite, e qualche riuscita — non vale zero:
zero direbbe «gratis», e l'assenza è la verità. La somma le salta, chi chiama le conta.
"""

from collections.abc import Mapping
from datetime import date, datetime, time, timedelta
from enum import StrEnum

from app.domain.rules import PANTRY_TZ


class SpendingPeriod(StrEnum):
    """I tre periodi della schermata, decisi da Mattia il 2026-10-09."""

    MONTH = "month"
    LAST_30_DAYS = "30d"
    ALL = "all"


LAST_DAYS = 30
# otto decimali: la somma di float lascia resti (0.30000000000000004) che non sono soldi
MONEY_DIGITS = 8
SHARE_DIGITS = 4

# Il nome a video di ogni sezione (`llm_calls.call_site`, cioè `LlmCallSite`). Chiavi
# stringa e non membri dell'enum: il database può contenere una sezione che il codice in
# esercizio non conosce (un ramo nuovo, una sezione tolta), e le ultime due arrivano
# stanotte da S12 e da R8 su altri rami. Una sezione assente da qui si mostra col suo
# valore com'è: brutta, ma vera e senza rompere niente.
CALL_SITE_LABELS: dict[str, str] = {
    "term_decision": "Abbinare gli ingredienti dell'import",
    "term_collapse": "Unire i doppioni dell'import",
    "unit_forms": "Forme delle unità",
    "recipe_draft": "Ricette scritte con l'AI",
    "recipe_variant": "Varianti con l'AI",
    "ingredient_emoji": "Figure della dispensa",
}


def call_site_label(call_site: str) -> str:
    return CALL_SITE_LABELS.get(call_site, call_site)


def period_days(
    period: SpendingPeriod, today: date, first_call: date | None
) -> tuple[date, date]:
    """Il primo e l'ultimo giorno del periodo, compresi; l'ultimo è sempre oggi.

    «Da sempre» parte dal giorno della prima chiamata registrata (in produzione il
    2026-09-17, quando è nato `llm_calls`), e senza chiamate è solo oggi. Una prima
    chiamata datata nel futuro (un orologio avanti) non sposta l'inizio dopo la fine.
    """
    if period is SpendingPeriod.MONTH:
        return today.replace(day=1), today
    if period is SpendingPeriod.LAST_30_DAYS:
        return today - timedelta(days=LAST_DAYS - 1), today
    if first_call is None:
        return today, today
    return min(first_call, today), today


def day_start(day: date) -> datetime:
    """La mezzanotte di quel giorno a Roma, come istante.

    La query confronta `created_at` (un istante) con `[day_start(primo),
    day_start(ultimo + 1))`: `ZoneInfo` sa quando l'ora cambia, quindi un giorno di 23 o
    25 ore resta un giorno.
    """
    return datetime.combine(day, time.min, tzinfo=PANTRY_TZ)


def daily_series(
    first: date, last: date, by_day: Mapping[date, float]
) -> list[tuple[date, float]]:
    """Ogni giorno del periodo con la sua spesa, quelli senza a zero.

    Qui lo zero è vero: è «nessuna chiamata con un costo quel giorno», non un costo
    sconosciuto messo a zero.
    """
    days = (last - first).days + 1
    series = []
    for offset in range(days):
        day = first + timedelta(days=offset)
        series.append((day, by_day.get(day, 0.0)))
    return series


def money(value: float) -> float:
    return round(value, MONEY_DIGITS)


def share(part: float, total: float) -> float:
    """La quota del totale, 0–1. Con un totale a zero non c'è niente da dividere."""
    if total <= 0:
        return 0.0
    return round(part / total, SHARE_DIGITS)
```

   ```python
   class SectionSpend:

       `cost_usd` è la somma dei soli costi dichiarati: una chiamata senza costo sta in
       `unpriced_calls`, non nella somma come zero.

   def _rome_day():

       Il fuso è scritto nella query come costante e non passato come parametro: questa
       espressione sta sia nel SELECT sia nel GROUP BY, e due parametri (`$1`, `$2`) con lo
       stesso valore per Postgres sono due espressioni diverse («must appear in the GROUP BY
       clause»). Il valore viene dal codice, mai da chi chiama.

   async def spend_by_section(
       session: AsyncSession, start: datetime, end: datetime

       """Le chiamate in `[start, end)`, sezione per sezione. L'ordine lo decide chi chiama."""
       rows = await session.execute(
           select(
               LlmCall.call_site,
               func.count(),
               func.count(LlmCall.cost_usd),
               func.coalesce(func.sum(LlmCall.cost_usd), 0.0),
           )
           .where(LlmCall.created_at >= start, LlmCall.created_at < end)
           .group_by(LlmCall.call_site)
       )
       return [
           SectionSpend(

               calls=calls,
               unpriced_calls=calls - priced,
               cost_usd=float(cost),
           )
           for call_site, calls, priced, cost in rows.all()
       ]


   async def spend_by_day(session: AsyncSession, start: datetime, end: datetime) -> dict[date, float]:
       """La spesa dichiarata di ogni giorno di Roma in `[start, end)` che ha chiamate."""
       day = _rome_day()
       rows = await session.execute(
           select(day, func.coalesce(func.sum(LlmCall.cost_usd), 0.0))
           .where(LlmCall.created_at >= start, LlmCall.created_at < end)
   ```

```python
"""Quanto è costata l'AI in un periodo, e come si divide (H1).

Tutto il calcolo sta qui e nel dominio: il frontend riceve somme, quote, nomi e giorni già
decisi, e li disegna.
"""

from datetime import date, timedelta

from sqlalchemy.ext.asyncio import AsyncSession

from app.domain.spending import (
    SpendingPeriod,
    call_site_label,
    daily_series,
    day_start,
    money,
    period_days,
    share,
)
from app.repositories.llm_calls import first_call_day, spend_by_day, spend_by_section
from app.schemas.spending import DaySpendOut, SectionSpendOut, SpendingOut


async def spending_report(
    session: AsyncSession, period: SpendingPeriod, today: date
) -> SpendingOut:
    first_call = await first_call_day(session) if period is SpendingPeriod.ALL else None
    first, last = period_days(period, today, first_call)
    start, end = day_start(first), day_start(last + timedelta(days=1))

    sections = await spend_by_section(session, start, end)
    by_day = await spend_by_day(session, start, end)
    total = money(sum(section.cost_usd for section in sections))
    # dalla più cara; a parità, quella con più chiamate, poi il nome: un ordine fisso, così
    # due periodi con le stesse cifre non si mostrano in due ordini
    ordered = sorted(
        sections,
        key=lambda section: (-section.cost_usd, -section.calls, call_site_label(section.call_site)),
    )
    return SpendingOut(
        period=period,
        first_day=first,
        last_day=last,
        total_usd=total,
        calls=sum(section.calls for section in sections),
        unpriced_calls=sum(section.unpriced_calls for section in sections),
        sections=[
            SectionSpendOut(
                call_site=section.call_site,
                label=call_site_label(section.call_site),
                cost_usd=money(section.cost_usd),
                share=share(section.cost_usd, total),
                calls=section.calls,
            )
            for section in ordered
        ],
        days=[
            DaySpendOut(day=day, cost_usd=money(cost))
            for day, cost in daily_series(first, last, by_day)
        ],
    )
```

```ts
// Le parole delle spese dell'AI. Solo scrittura: le cifre, i giorni e le quote li decide
// il server.

// Dollari, perché è quel che OpenRouter dichiara: una conversione in euro sarebbe un
// cambio inventato. Il simbolo stretto («$» e non «USD»), dopo la cifra, come scrive
// l'italiano; fra i due uno spazio che non va a capo.
const CENTS = new Intl.NumberFormat("it-IT", {
  style: "currency",
  currency: "USD",
  currencyDisplay: "narrowSymbol",
  minimumFractionDigits: 2,
  maximumFractionDigits: 2,
});
// Sotto il dollaro le cifre vere sono frazioni di centesimo (una decisione dell'import
// costa ~0,0001 $): due decimali scriverebbero «0,00 $» per un mese di spesa vera.
const FRACTIONS = new Intl.NumberFormat("it-IT", {
  style: "currency",
  currency: "USD",
  currencyDisplay: "narrowSymbol",
  minimumFractionDigits: 2,
  maximumFractionDigits: 4,
});
const SMALLEST = 0.0001;

export function formatUsd(value: number): string {
  if (value <= 0) return CENTS.format(0);
  // sotto il decimillesimo «0,0000 $» direbbe zero, e zero non è
  if (value < SMALLEST) return `< ${FRACTIONS.format(SMALLEST)}`;
  return value < 1 ? FRACTIONS.format(value) : CENTS.format(value);
}

const PERCENT = new Intl.NumberFormat("it-IT", { style: "percent", maximumFractionDigits: 0 });

export function formatShare(share: number): string {
  // «0%» accanto a una barra che si vede direbbe il falso
  if (share > 0 && share < 0.005) return "< 1%";
  return PERCENT.format(share);
}

// Un giorno `AAAA-MM-GG` come data locale: la data è già quella di Roma, e costruirla dai
// numeri del calendario non la fa slittare col fuso di chi guarda.
function localDate(iso: string): Date {
  const [year, month, day] = iso.split("-").map(Number);
  return new Date(year, month - 1, day);
}

export function formatDay(iso: string): string {
  return localDate(iso).toLocaleDateString("it-IT", { day: "numeric", month: "long" });
}

export function formatDayShort(iso: string): string {
  return localDate(iso).toLocaleDateString("it-IT", { day: "numeric", month: "short" });
}

// «dall'1», «dall'8», «dall'11»: davanti a un numero che si legge con una vocale
const VOWEL_DAYS = new Set([1, 8, 11]);
const from = (day: number) => (VOWEL_DAYS.has(day) ? `dall'${day}` : `dal ${day}`);
const to = (day: number) => (VOWEL_DAYS.has(day) ? `all'${day}` : `al ${day}`);
const monthName = (date: Date) => date.toLocaleDateString("it-IT", { month: "long" });

/** Il periodo in parole: «13 ottobre», «dall'1 al 13 ottobre», «dal 14 settembre al 13
 * ottobre»; l'anno solo quando cambia. */
export function formatRange(first: string, last: string): string {
  if (first === last) return formatDay(first);
  const a = localDate(first);
  const b = localDate(last);
  if (a.getFullYear() !== b.getFullYear()) {
    return `${from(a.getDate())} ${monthName(a)} ${a.getFullYear()} ${to(b.getDate())} ${monthName(b)} ${b.getFullYear()}`;
  }
  if (a.getMonth() !== b.getMonth()) {
    return `${from(a.getDate())} ${monthName(a)} ${to(b.getDate())} ${monthName(b)}`;
  }
  return `${from(a.getDate())} ${to(b.getDate())} ${monthName(b)}`;
}

export function callsText(calls: number): string {
  return calls === 1 ? "1 chiamata" : `${calls} chiamate`;
}

/** Le chiamate senza un costo dichiarato (decisa da Mattia il 2026-10-13): il
 * totale non le comprende, e lo si dice invece di lasciarlo credere completo. */
export function unpricedText(unpriced: number): string {
  return unpriced === 1
    ? "1 senza un costo dichiarato da OpenRouter (di solito, una chiamata fallita): non è nel totale."
    : `${unpriced} senza un costo dichiarato da OpenRouter (di solito, chiamate fallite): non sono nel totale.`;
}

/** Il giorno più caro, che dà l'altezza alle colonne; il primo a parità. `null` se nessun
 * giorno ha una spesa. */
export function peakDay(days: DaySpend[]): DaySpend | null {
  let peak: DaySpend | null = null;
  for (const day of days) {
    if (day.cost_usd > 0 && (peak === null || day.cost_usd > peak.cost_usd)) peak = day;
  }
  return peak;
}
```

```tsx
import { Card } from "../../components/ui/Card";
import { formatDay, formatDayShort, formatRange, formatUsd, peakDay } from "./format";
import type { DaySpend } from "./types";

// Una colonna ha accanto il suo spazio (un quinto della fetta: ~2 px su un mese a 375 px)
// finché i giorni sono al più due mesi; oltre, la fetta scende sotto i 5 px e lo spazio la
// cancellerebbe: le colonne si toccano e fanno una sagoma.
const GAPPED_UP_TO = 62;
const GAP = 0.2;
// Con pochi giorni (i primi del mese) una colonna non si allarga oltre quella che avrebbe
// con quattordici: un giorno solo largo tutta la scheda sembrerebbe un riquadro, non un dato.
const MIN_SLOTS = 14;
// Una spesa minuscola accanto a una grossa resterebbe sotto il pixel: due unità su cento la
// tengono visibile, senza farla sembrare grande.
const MIN_HEIGHT = 2;

/** «Per giorno» (H1): una colonna per ogni giorno con una spesa, alta in proporzione al
 * giorno più caro, sopra una linea di base; i giorni a zero non hanno colonna.
 *
 * Un `viewBox` di una unità per giorno e cento in altezza, stirato sulla larghezza della
 * scheda (`preserveAspectRatio="none"`): niente misure in pixel da calcolare, niente
 * scorrimento di lato, nemmeno con un anno di giorni. Per questo niente angoli arrotondati
 * (si deformerebbero) e la linea di base non scala (`non-scaling-stroke`). Niente testo
 * dentro l'SVG: il giorno più caro e le date stanno in HTML, dove li misura lo scanner del
 * contrasto.
 *
 * Le colonne non si toccano una per una: trenta colonne su 375 px sono larghe 10 px, sotto
 * i 44 di casa. Chi non vede ha il riassunto nel nome dell'immagine e la tabella dei giorni
 * con una spesa. Senza nessun giorno con una spesa non disegna niente: un grafico vuoto
 * non dice niente che il totale non dica già. */
export function DailyColumns({ days }: { days: DaySpend[] }) {
  const peak = peakDay(days);
  if (peak === null) return null;

  const count = days.length;
  const first = days[0].day;
  const last = days[count - 1].day;
  const width = count < MIN_SLOTS ? ((1 - GAP) * count) / MIN_SLOTS : count <= GAPPED_UP_TO ? 1 - GAP : 1;
  const height = (cost: number) => Math.max((cost / peak.cost_usd) * 100, MIN_HEIGHT);
  const peakText = `Il giorno più caro: ${formatDay(peak.day)}, ${formatUsd(peak.cost_usd)}`;

  return (
    <Card>
      <p className="text-sm text-ink-soft">{peakText}</p>
      <svg
        role="img"
        aria-label={`Costo per giorno, ${formatRange(first, last)}. ${peakText}.`}
        viewBox={`0 0 ${count} 102`}
        preserveAspectRatio="none"
        className="mt-2 block h-32 w-full"
      >
        {days.map((day, index) =>
          day.cost_usd > 0 ? (
            <rect
              key={day.day}
              data-day={day.day}
              x={index + (1 - width) / 2}
              width={width}
              y={100 - height(day.cost_usd)}
              height={height(day.cost_usd)}
              className="fill-brand"
            />
          ) : null
        )}
        <line
          x1="0"
          x2={count}
          y1="101"
          y2="101"
          strokeWidth="1"
          vectorEffect="non-scaling-stroke"
          className="stroke-line"
        />
      </svg>
      <div className={`flex pt-1 text-xs text-ink-faint ${first === last ? "justify-center" : "justify-between"}`}>
        <span>{formatDayShort(first)}</span>
        {first !== last && <span>{formatDayShort(last)}</span>}
      </div>
      <table className="sr-only">
        <caption>I giorni con una spesa</caption>
        <tbody>
          {days
            .filter((day) => day.cost_usd > 0)
            .map((day) => (
              <tr key={day.day}>
                <th scope="row">{formatDay(day.day)}</th>
                <td>{formatUsd(day.cost_usd)}</td>
              </tr>
            ))}
        </tbody>
      </table>
    </Card>
  );
}
```

```python
"""Semina e pulizia per le prove delle spese dell'AI (H1) in `frontend/e2e/`. Non è un test
di pytest.

Lo stack e2e non ha spese: `.env.e2e` lascia vuota la chiave di OpenRouter, e una chiamata
che sfugge a uno stub si ferma su `LlmUnavailable` (al più una riga fallita, col costo
NULL). Le prove della schermata vogliono cifre vere: questo file scrive in `llm_calls` delle
righe col loro costo, nessuna rete, e le toglie. Le riconosce dal `generation_id`, che
comincia con `e2e-spese-` (anche quella fallita, che in esercizio non l'avrebbe).

Le righe, negli ultimi 30 giorni 0,025 $:

- oggi: `recipe_draft` 0,012 e 0,008, una `recipe_draft` fallita senza costo, e
  `e2e_sconosciuta` 0,001 — una sezione che il backend non conosce, da mostrare grezza;
- tre giorni fa: `term_decision` 0,004.

Si lancia dentro il container del backend, dove `./backend` è montato su `/app`:

    $E2E exec -T backend python tests/e2e_spese.py seed
    $E2E exec -T backend python tests/e2e_spese.py clean

`clean` si può chiamare prima di seminare: toglie anche gli avanzi di un giro interrotto.

Scrive e cancella nel database, quindi **si rifiuta di partire fuori dallo stack e2e**:
vuole `SPENA_E2E=1`, che sta solo in `.env.e2e`.

Non si chiama `test_*.py` apposta: pytest non lo raccoglie.
"""

import os
import sys

if os.environ.get("SPENA_E2E") != "1":
    raise SystemExit(
        "e2e_spese.py scrive e cancella nel database: gira solo sullo stack "
        "spena-e2e, che porta SPENA_E2E=1 da .env.e2e. Qui manca, e non parto."
    )

import asyncio  # noqa: E402
import json  # noqa: E402
from datetime import UTC, datetime, timedelta  # noqa: E402

from sqlalchemy import delete  # noqa: E402

from app.core.db import SessionLocal  # noqa: E402
from app.db.models.llm_call import LlmCall  # noqa: E402

MARK = "e2e-spese-"

# (sezione, riuscita, costo, giorni fa)
ROWS = [
    ("recipe_draft", True, 0.012, 0),
    ("recipe_draft", True, 0.008, 0),
    ("recipe_draft", False, None, 0),
    ("e2e_sconosciuta", True, 0.001, 0),
    ("term_decision", True, 0.004, 3),
]


async def seed() -> dict:
    now = datetime.now(UTC)
    async with SessionLocal() as session:
        for index, (call_site, ok, cost, days_ago) in enumerate(ROWS):
            session.add(
                LlmCall(
                    call_site=call_site,
                    ok=ok,
                    model="e2e/finto",
                    generation_id=f"{MARK}{index}",
                    cost_usd=cost,
                    created_at=now - timedelta(days=days_ago),
                )
            )
        await session.commit()
    return {"rows": len(ROWS)}


async def clean() -> dict:
    async with SessionLocal() as session:
        result = await session.execute(
            delete(LlmCall).where(LlmCall.generation_id.like(f"{MARK}%"))
        )
        await session.commit()
    return {"rows": result.rowcount}


def main() -> None:
    command = sys.argv[1] if len(sys.argv) > 1 else ""
    if command == "seed" and len(sys.argv) == 2:
        print(json.dumps(asyncio.run(seed())))
    elif command == "clean" and len(sys.argv) == 2:
        print(json.dumps(asyncio.run(clean())))
    else:
        raise SystemExit("uso: e2e_spese.py seed | clean")


if __name__ == "__main__":
    main()
```

```ts
/** Il contrasto WCAG 1.4.11 di un segno SVG: il suo `fill` calcolato contro il fondo del
 * primo antenato che ne dipinge uno (la scheda). `contrastoSegno` legge il
 * `backgroundColor`, che un `<rect>` non ha: per il resto è la stessa risalita. */
async function contrastoRiempimento(segno: Locator) {
  return segno.evaluate((el) => {
    const view = el.ownerDocument.defaultView;
    const canali = (colore: string) => (colore.match(/[\d.]+/g) ?? []).map(Number);
    const luminanza = (colore: string) => {
      const [r, g, b] = canali(colore).map((v) => {
        const s = v / 255;
        return s <= 0.03928 ? s / 12.92 : ((s + 0.055) / 1.055) ** 2.4;
      });
      return 0.2126 * r + 0.7152 * g + 0.0722 * b;
    };

    const proprio = view.getComputedStyle(el).fill;
    let fondo: string | null = null;
    for (let nodo = el.parentElement; nodo; nodo = nodo.parentElement) {
      const stile = view.getComputedStyle(nodo);
      const alfa = canali(stile.backgroundColor)[3] ?? 1;
      if (alfa > 0) {
        fondo = stile.backgroundColor;
        break;
      }
    }

    const a = luminanza(proprio);
    const b = luminanza(fondo ?? "rgb(255, 255, 255)");
    return {
      colore: proprio as string,
      fondo: fondo as string | null,
      rapporto: (Math.max(a, b) + 0.05) / (Math.min(a, b) + 0.05),
    };
  });
}
```
